# 宠物叫声数据集采集指南

目标：训练一个能区分 **7 类宠物叫声 + 3 类拒绝类** 的分类器，替换 `petvoice_service.py` 里现在的规则分类器（合成集上界 66~88%，低信噪比 58%，真实叫声从未验证）。

> 一句话结论先说：**网上能找到的素材足够训出可用的模型，但有四条硬标准必须卡死，否则训出来的东西在真实场景里立刻失效。**

---

## 一、目录结构（文件夹名 = 标签）

```
k1-vision/datasets/voice_clips/
    bark/      犬吠：短促爆发，宽带
    howl/      长嚎：长音，基频缓慢下滑（分离焦虑的典型）
    growl/     低吼：低频、强幅度调制、持续（威胁）
    meow/      喵叫：中高频，基频先升后降
    purr/      呼噜：低频周期脉冲，能量低而稳
    hiss/      哈气：宽带噪声，谱平坦度高，无基频
    scream/    尖叫：高基频、高能量、长音（疼痛/极度恐惧）
    human/     人声（拒绝类）
    noise/     环境噪声：空调、电视、车流、洗衣机（拒绝类）
    silence/   安静房间底噪（拒绝类）
```

三个拒绝类**不是可选项**。没有它们，人说话会被判成 bark、电视声会被判成 hiss——识别率再高也不可用。脚本会检查并警告。

中文文件夹名也认（`吠叫/`、`喵叫/`、`人声/`…），脚本内有别名表。

## 二、数量门槛

| 项 | 底线 | 推荐 | 为什么 |
|---|---|---|---|
| 每类窗数 | 200 | **400~800** | 0.96 s 窗、50% 重叠 ≈ 2 窗/秒，即每类 100~400 秒有效发声 |
| 每类个体数 | 4 只 | **≥10 只** | 少于此数，模型学的是「这只动物的音色」 |
| 每类录制条件 | 2 种 | **≥3 种**（手机/摄像头/不同距离） | 家用麦克风与网络素材的频响差异极大 |
| 总时长 | 15 分钟 | **60 分钟以上** | — |

**为什么强调个体数**：单一动物的素材里，音色、基频、共振峰是固定常数，模型会把这些当成判别依据。换一只同种的动物，准确率会断崖式下跌。这个现象在犬吠上尤其明显——不同品种的吠叫基频能差 3 倍。

## 三、素材从哪来（既然没有宠物）

### 1. 公开数据集（先跑通用性，再补场景）

| 数据集 | 内容 | 用途 |
|---|---|---|
| **ESC-50** | 2000 段 5 秒环境声，含 dog / cat / rooster 等 | 最省事，直接可用；但只有大类，无 bark/howl 细分 |
| **AudioSet**（动物子集） | YouTube 来源，量大 | 需用 `yt-dlp` 按 ID 下载，实际可用率约 60% |
| **DCASE Task 3 / 5** | 声音事件检测，含动物 | 标注质量高，偏学术场景 |
| **Kaggle: dog bark / cat sound** | 若干小数据集 | 质量参差，**务必先听** |
| **UrbanSound8K** | 城市噪声 | 正好用作 `noise` 拒绝类 |

ESC-50 的 dog 类可作为「大类可行」的基线验证，但**不能替代细分标注**——它不区分吠叫/长嚎/低吼。

### 2. 视频平台（细分素材的主要来源）

B 站、YouTube 上「狗分离焦虑嚎叫」「猫发情叫」「猫哈气」这类视频是 bark/howl/growl/hiss/scream 的主要来源。用 ffmpeg 抽音频：

```bash
# 抽单声道 16 kHz，顺带滤掉 80 Hz 以下的空调轰鸣和 7 kHz 以上的嘶声
ffmpeg -i input.mp4 -vn -ac 1 -ar 16000 -af "highpass=f=80,lowpass=f=7000" out.wav
```

`-vn` 丢掉视频轨、`-ac 1` 转单声道、`-ar 16000` 直接对齐训练采样率（省掉重采样这一步的失真）。

### 3. 自己录（补充真实场景，优先级最高）

哪怕没有宠物，也可以：

- 去宠物店/宠物医院/朋友家，用手机录 10 分钟（**这是最有价值的数据**，因为麦克风与部署环境最接近）
- 家里没人时录 2 分钟「安静底噪」→ `silence`
- 开空调/电视/洗衣机各录 2 分钟 → `noise`
- 自己念几段话 → `human`

## 四、四条硬标准（踩过才知道有多致命）

### ① 带 BGM 的素材一律不要

短视频平台的宠物视频**大部分配了背景音乐**。音乐是强周期信号，模型的捷径是学音乐而不是学叫声，结果就是「换个 BGM 就全错」。而且这种失败在验证集上完全看不出来——因为验证集也带 BGM。

**判断方法**：戴上耳机听 10 秒。有旋律、有鼓点、有人声解说 → 弃用。宁可少 50 段素材，也不要混进 10 段带 BGM 的。

### ② 同一只动物的全部片段必须分到同一侧

同一只狗的 10 段吠叫若被拆进 train/val/test，验证集考的其实是「能不能认出这只狗」。**实测这类泄漏会让 macro-F1 虚高 10~20 个点**，而且是评委最容易追问的地方（"你怎么划分数据集的？"）。

脚本的处理：文件名写成 `个体ID__描述.wav`，用 `--group-by prefix` 切分，同一个个体的全部片段强制同侧。

```
bark/dog01__bark_001.wav
bark/dog01__bark_002.wav      ← 与上一行同组，必同侧
bark/dog02__bark_001.wav      ← 不同个体，可异侧
```

### ③ 不要按声音直接标情绪

「焦虑」和「求关注」在声学上几乎不可分——都是高频、重复、拖长。让人凭听感标情绪，两个人标同一段音频的一致率通常只有 50~60%，训出来的标签本身就是噪声。

正确做法见第六节。

### ④ 每个类别至少来自 4 个不同个体

低于 4 个，训练集和验证集几乎必然共享音色特征。这类模型的典型症状是：验证集 85%，换一只动物掉到 40%。

## 五、完整命令

```bash
# ① 先看统计，不写文件（强烈建议先跑这个）
.venv-train/Scripts/python.exe k1-vision/audio_to_dataset.py \
    --src k1-vision/datasets/voice_clips \
    --out k1-vision/datasets/voice \
    --group-by prefix --dry-run

# ② 正式生成
.venv-train/Scripts/python.exe k1-vision/audio_to_dataset.py \
    --src k1-vision/datasets/voice_clips \
    --out k1-vision/datasets/voice \
    --group-by prefix

# ③ 训练 + 评估 + 导出 ONNX（GPU，几十分钟）
.venv-train/Scripts/python.exe k1-vision/train_voice_cnn.py \
    --data k1-vision/datasets/voice --epochs 60 --export

# ④ int8 量化 + 精度校验
.venv-train/Scripts/python.exe k1-vision/quant_voice_int8.py \
    --onnx runs/voice/voice_cnn.onnx --data k1-vision/datasets/voice
```

脚本会主动拦下这些情况：

- 某类在训练集里 0 样本 → **严重警告**（模型永远学不会该类）
- 某类窗数 < 200 → 警告
- val macro-F1 > 0.97 → **主动提示先怀疑数据泄漏**，而不是庆祝
- 量化后一致率 < 0.97 → 给三步排查顺序

## 六、情绪怎么处理（不要跳过这一节）

用户要的是「识别宠物情绪」。**情绪无法从声音直接测量**，只能推断。方案里的立场是：

> 不做「情绪分类」，做「叫声类型 × 情境 × 时长」的联合推断，且始终带置信度、允许输出「不确定」。

具体实现已经在代码里（`petvoice_service.py` 的 `STATE_RULES`）：

| 叫声 | 可能状态（按先验排序） |
|---|---|
| bark | alert 0.55 / threat 0.25 / play 0.20 |
| howl | anxiety 0.65 / alert 0.25 / lonely 0.10 |
| growl | threat 0.80 / alert 0.20 |
| meow | hunger 0.40 / attention 0.35 / discomfort 0.25 |
| purr | relaxed 0.85 / content 0.15 |
| hiss | threat 0.90 / fear 0.10 |
| scream | pain 0.60 / fear 0.40 |

**最终状态还要叠加**：重复次数（3 分钟内 5 次吠叫 vs 1 次）、持续时长、视觉行为、时段（凌晨 vs 白天）。单帧声音只能给「倾向」，给不了结论。

这样做的好处是诚实且可辩护：评委问「你怎么知道它焦虑」，答案是「长嚎 + 独处 + 连续 8 分钟 + 来回踱步，四路证据指向分离焦虑」，而不是「模型说是焦虑」。

## 七、预期指标与判读

| 数据规模 | 预期 macro-F1 | 说明 |
|---|---|---|
| 每类 100 窗 | 45~60% | 只能区分大类（吠叫 vs 喵叫） |
| 每类 400 窗 | **60~75%** | 可用的下限，能上板演示 |
| 每类 800+ 窗、10+ 个体 | 75~85% | 有说服力 |
| 任何规模 > 90% | **先查泄漏** | 这个任务很难做到 90%，除非数据有问题 |

**比总体准确率更重要的是混淆矩阵**。要盯住三对：

- `bark ↔ growl`：都是低频宽带，靠时长和调制深度区分
- `meow ↔ scream`：都是中高频，靠基频走向和能量
- `purr ↔ noise`：都是低频稳态，**这是最危险的一对**——空调声被判成呼噜会让系统一直报「宠物很放松」

后一对的正确处理不是加大模型，是**补高质量的 noise 素材**（真实家电录音，不是白噪声）。

## 八、上板部署

```bash
# 1) 拷到 K1
scp runs/voice/voice_cnn_int8.onnx root@192.168.88.10:/root/k1-ai/models/

# 2) 重启服务（会自动加载，加载失败会回退规则分类并在日志留痕）
ssh root@192.168.88.10 "systemctl restart k1-petvoice"

# 3) 确认走的是 ONNX 而不是规则
ssh root@192.168.88.10 "journalctl -u k1-petvoice -n 30 | grep -i 'onnx\|mode'"
```

**关键**：`petvoice_service.py` 的加载逻辑是「模型存在且能加载 → 用 ONNX，否则回退规则」，两者接口完全一致。所以部署是安全的——最坏情况退回现在的能力，不会崩。

但**回退是静默的**，必须看日志确认 `mode = onnx`，否则你以为在跑模型、实际跑的是规则。
