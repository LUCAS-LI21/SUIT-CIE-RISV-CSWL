# 宠物本地知识库（K1 板端，纯检索 + 受控改写）

一个跑在 K1 开发板上的最小可用 RAG：**36 条宠物健康知识，14 KB 文本，纯 Python 标准库，零第三方依赖**。
回答医疗类问题时**完全不经过模型**，从根上避免 0.6B 小模型篡改事实。

---

## 一、它解决什么问题

Qwen3-0.6B 实测在生活常识上 8 题错 7 题（把沸点答成 212°C、冰箱冷藏室答成 20–24°C、猫体温高风险题也会编）。
原因是**容量**：36 万亿 token 的语料被压进 0.44B 个非嵌入参数，装不下就只能丢和混。

所以做法不是"训练它"，而是**把知识挪到模型外面**：

| | 裸模型 | 接知识库后 |
|---|---|---|
| 猫能不能喝牛奶 | 可能答"可以，注意温度" | **"不建议，乳糖不耐会导致腹泻"**（知识库原文） |
| 冰箱冷藏室几度 | 20–24℃，错一个数量级 | 知识库没有这条 → 明确说没有，不编 |
| 单次耗时 | 5–25 秒 | **9.1 ms**（检索） |
| 内存 | 995–1609 MB | **10.4 MB** |
| 算力占用 | 4 个 IME 核 | 几乎为 0 |

**知识库不是模型的一部分**，不需要训练、不需要重编译、不吃算力。它就是一份 JSON。

## 二、文件清单

| 文件 | 说明 |
|---|---|
| `pet_kb.json` | 知识条目，36 条，14 KB。可直接手改 |
| `rag.py` | 检索引擎 + 回答策略 + HTTP 服务，11 KB |
| `tune.py` | 阈值调参工具，打印正负样本得分分布 |
| `petkb.service` | systemd 单元，开机自启 |

板端位置：`/root/petkb/`，服务名 `petkb`，端口 `11435`。

---

## 三、回答策略（以实测为准，不是拍脑袋）

```
用户问题
   │
   ├─ 检索得分 < 7.0 ──────────→ 明确回答"知识库没有"，不推测
   │
   └─ 命中 ────────────────────→ 直接返回知识原文
                                  （默认永不经过模型）
```

**为什么不让模型改写：实测反例**

给模型一句资料：「葡萄和葡萄干可导致犬急性肾衰竭，没有已知安全剂量」，问「狗能吃葡萄吗」，它答 **「能。」**

同一轮测试里，给它「布丁每天喂食两次，每次30克」问每天多少克，它答 **60克**（对）。

结论：**它能照抄，但不能用资料做是非判断**。所以凡是命中知识库的，一律回退原文。改写路径保留为 `--rewrite` 实验开关，**不建议在演示中打开**。

代码里保留了数字校验（改写结果出现资料外的数字即回退），作为将来换更大模型时的安全网。

## 四、怎么加知识

往 `pet_kb.json` 的 `entries` 里加一条：

```json
{
  "id": "unique_id",
  "cat": "分类名",
  "q": "这条知识对应的标准问法",
  "keys": ["关键词1", "关键词2", "口语说法"],
  "a": "答案，二到四句，关键数字必须写清楚",
  "risk": "high"
}
```

规则：

- `keys` 要覆盖**用户可能的口语说法**，不只是书面词（例如"拉稀""喝奶""尿不出"）。命中关键词每条加 1.5 分，最多计 3 条。
- `risk: "high"` 用于**医疗、中毒、急救、剂量**，这类条目模型不参与改写。
- 加完跑 `python3 rag.py --eval` 和 `python3 tune.py`，确认没有把负样本顶上去。

## 五、部署与使用

### 部署到板子

```bash
ADB="/e/AndroidStudio/android/sdk/platform-tools/adb.exe"
MSYS_NO_PATHCONV=1 "$ADB" shell 'mkdir -p /root/petkb'
MSYS_NO_PATHCONV=1 "$ADB" push pet_kb.json /root/petkb/
MSYS_NO_PATHCONV=1 "$ADB" push rag.py /root/petkb/
MSYS_NO_PATHCONV=1 "$ADB" push petkb.service /etc/systemd/system/
MSYS_NO_PATHCONV=1 "$ADB" shell 'systemctl daemon-reload && systemctl enable --now petkb'
```

### 自证：回答确实来自板子（一键）

双击 **`verify-local.bat`**（或 `node verify-local.js`），它做四件互相印证的事：

| 检查 | 说明 |
|---|---|
| 电脑侧 `netstat` + `tasklist` | 11435 端口在本机由 **adb.exe** 持有，不是 python → 知识库进程不在电脑上 |
| 板内 `ss -lntp` | `python3` 监听 11435、`ollama` 监听 11434，都带板上的 PID |
| 板内 `journalctl -u petkb` | 每次查询留一行 `[ASK] q=... hit=... score=...`，得分能和网页上显示的对上 |
| 板内 `journalctl -u ollama` | 每次生成留一行 `POST /api/chat`，耗时和网页指标对得上 |

**这是判断"有没有幻觉"的唯一硬标准**：网页上的数字必须能在板子的 journal 里找到同一条记录。找不到，就是没走板子。

也可以手动看：

```bash
ADB="/e/AndroidStudio/android/sdk/platform-tools/adb.exe"
MSYS_NO_PATHCONV=1 "$ADB" shell 'journalctl -u petkb -f'     # 实时看知识库查询
MSYS_NO_PATHCONV=1 "$ADB" shell 'journalctl -u ollama -f'    # 实时看模型请求
```

### 三种用法

**① 网页（推荐）** — 双击 `k1-chat/start-chat.bat`，右上角「知识库 开」。命中会显示条目 id、得分、模式和耗时；未命中会在气泡上方提示"以下由模型自由回答"。

**② 命令行**（在板子上）

```bash
cd /root/petkb
python3 rag.py "猫能喝牛奶吗"        # 完整回答
python3 rag.py --raw "猫能喝牛奶吗"  # 只看得分和候选条目
python3 rag.py --eval               # 检索准确率评测
python3 tune.py                     # 正负样本分界诊断
```

**③ HTTP 接口**

```
GET http://127.0.0.1:11435/ask?q=猫能喝牛奶吗
GET http://127.0.0.1:11435/health
```
房间外访问需先 `adb forward tcp:11435 tcp:11435`。

## 六、检索原理

中文没有空格，所以按**字符 bigram** 切分（"猫能喝牛奶" → 猫能/能喝/喝牛/牛奶），再用 BM25 打分，叠加关键词命中加分。
负样本与正样本的得分分布：

| | 最低/最高 | 典型值 |
|---|---|---|
| 正样本（20 条真实问法） | 最低 **7.59** | 12–25 |
| 负样本（18 条域外问题） | 最高 **6.41** | 0–3 |

阈值 7.0 落在这个空隙里。实测 20 条正样本全中、18 条负样本全拒。

**没有用向量检索**。原因：K1 上再跑一个 embedding 模型要多占几百 MB 和算力，而 36 条知识用 BM25 已经足够；等条目涨到几百条再考虑向量化。

## 七、已知限制

1. **只覆盖写了的内容**。问"猫粮多少钱"不会被当成知识库问题（得分不够），会转由模型自由回答，答案不可信。
2. **不会跨条推理**。"猫发烧还拉稀怎么办" 只会命中体温那一条，不会综合两条。
3. **口语理解有限**。说"主子不吃饭"这种别名，需要把别名写进 `keys` 才认。
4. **知识条目需要人工保证正确**。这 36 条按常规兽医共识编写，没有经过执业兽医审核，比赛中若有医疗展示环节建议加一句免责说明。
